## Что это

Плагин для [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) (dsh). Он добавляет на боковую панель отдельную панель «Возможности» и сводит в один наглядный интерфейс три задачи, ради которых обычно приходится править конфиги и лезть в исходники:

- **Кастомизация промптов**: блокировка, замена, добавление и сортировка секций системного промпта по имени + источнику;
- **Управление наборами скиллов**: импорт, группировка, включение и выключение скиллов;
- **Подключение MCP Server**: добавление MCP Server и перекрытие с включением/выключением на уровне пресета или отдельного инструмента.

Все изменения применяются через собственные точки расширения плагина — исходный код DSH не трогается; промпты и каталог инструментов начинают действовать на модель сразу после сохранения.

## Ключевые возможности

- **Управление секциями промпта**: блокировка / замена / добавление / сортировка перетаскиванием, плюс живой предпросмотр итогового системного промпта в правой колонке; **глобальный перехват**: секции системного промпта, которые вставляет любой плагин в любом скоупе (включая сессионные секции, динамически регистрируемые в `agent/created`), попадают в редактируемый список, и их можно заблокировать / заменить / отсортировать. На стороне хоста есть ещё read-only маршрут `/api/prompt-customizer/session`: он показывает реальный промпт и каталог инструментов в скоупе агента последней активной корневой сессии (отдельной вкладки «Текущая сессия» в самой панели нет).
- **Фазы и слои пресетов**: у фазы ввода, фазы управляемого сжатия и постоянной фазы свои списки секций, своё пространство сортировки и свой каталог инструментов; переключатель пресетов сверху задаёт цель редактирования, и кастомизация одного пресета действует только на него.
- **Редактирование одного пресета (2.0.0)**: кастомизация промптов и инструментов сохраняется и применяется только по **пресету агента**; уровень воркспейса для промптов/инструментов удалён (исходники заархивированы, данные в спящем режиме, не читаются, не пишутся и не бэкапятся). Понятие воркспейса по-прежнему используется для MCP / скиллов / cwd.
- **Каталог инструментов**: инструменты скрываются или возвращаются по фазам, панель показывает сравнение «видит модель / всего в реестре», и обёртка `run_code` в PTC / Code Mode тоже учитывается корректно.
- **Секции промптов инструментов**: вкладка «Инструменты» показывает связь секций `tool:*` с группами инструментов (например, `tool:jobs` → `job_kill/job_list/job_output`), а вкладка «Промпты» позволяет независимо их блокировать / заменять / сортировать; description инструмента показывается только для чтения, JSON Schema в редактирование промптов не входит.
- **Управление скиллами**: группировка в бандлы, импорт ZIP / папок, два уровня переключателей (глобальный / пресета), диагностика корней скиллов и согласованности их состава.
- **Управление MCP**: подключение вставкой JSON / YAML, строки Server, принадлежащие пресету, двухуровневое перекрытие (глобальное / пресета), включение и выключение на уровне инструментов, готовые шаблоны конфигов; глобальные Server сохраняются на диск в `$DSH_HOME/mcps/<serverName>/mcp.json` и после старта автоматически возвращаются в память.
- **Переменные промпта**: встроенные переменные даты, хоста, окружения и т. п., маппинг `process.env` и чёрный список секретов.

## Установка

Профиль Web:

```bash
dsh plugin --profile web add dsh-prompt-customizer
```

Десктоп (DeepSeek Harness Desktop):

```bash
dsh plugin --profile desktop add dsh-prompt-customizer
```

Или установка из локального клона:

```bash
dsh plugin --profile web add /path/to/dsh-prompt-customizer
```

**2.2.2 (текущая версия)**: свёрнутые PTC-инструменты теперь управляются чекбоксами (`run_code` закреплён навсегда; глобальные/унаследованные инструменты действительно удаляются из PTC SDK, а собственные инструменты агента/пресета только перехватываются во время выполнения); совместимо и проверено на **DSH 0.2.2-rc.3**; **2.1.3** (**исправление сохранения глобальных MCP на диске**: глобальные добавление / включение-выключение / удаление / редактирование пишутся в `$DSH_HOME/mcps/<serverName>/mcp.json` и после старта возвращаются в память, а не в `cordis.yml` в корне профиля, который DSH вычищает при запуске, и не в виртуальный реестр плагина в SQLite; уровень пресета по-прежнему пишет patch профиля, уровень воркспейса — `.mcp.json` проекта; редактирование одного пресета; **глобальный перехват системного промпта**: список и предпросмотр сливаются с реальной сборкой активного агента того же пресета, так что динамически вставленные плагином сессионные секции можно перечислить и заблокировать; **каталог инструментов из того же источника, что реальная сессия**: видимый каталог в правой колонке теперь берётся из `ctx.tools.schemas(agent)`, а не показывает только слой пресета; **обнаружение перекрытия одноимённым**: нативные инструменты, перекрытые одноимённым инструментом плагина, безусловно попадают в пул скрытых только для чтения, а чисто новые сессионные инструменты плагина тоже перечисляются как есть; дописаны регрессионные тесты для пула скрытых инструментов, статуса скиллов воркспейса, кэша сводок провайдера и очереди записи; глобальное редактирование MCP поддерживает JSON/YAML; активный пресет агента точно определяется по `composedPreset`; закрыты регрессии по изоляции промптов и инструментов пресетов A/B, восстановлению после удаления плагина и неизменности исходного текста). Соответствие версий, изменения по версиям и записи об адаптации — в [docs/upgrades/README.md](docs/upgrades/README.md).

## Быстрый старт

1. Откройте dsh Web UI и нажмите **Возможности** на боковой панели.
2. Выберите вкладку **Промпты** и сверху — пресет агента, который хотите редактировать.
3. Правьте в одном из трёх режимов — Промпты / Инструменты / Пресеты, — затем нажмите **Сохранить**; предпросмотр справа сразу покажет, что именно получит модель.

Промпты и инструменты настраиваются отдельно для каждой фазы — «Фаза ввода / Постоянная фаза / Фаза управляемого сжатия»; переключение вкладки фазы показывает её собственные чекбоксы и предпросмотр.

## Где хранится конфигурация

- **Всё в одном SQLite-файле**: `~/.dsh/prompt-customizer/prompt-customizer.db` (WAL, встроенный в Node `node:sqlite`, без внешних зависимостей). Кастомизация пресетов, перекрытие MCP / включение-выключение инструментов и реестры скиллов — все в этой одной базе; сами глобальные MCP лежат на диске в `$DSH_HOME/mcps`, а данные уровня воркспейса по промптам/инструментам остаются как спящие поля — их не читают и не пишут. Конфиги хоста (`cordis.patch.yml` / `.mcp.json`) и `.bundles.json` в корнях скиллов по-прежнему остаются файлами.
- **Ломающее обновление (1.0.0)**: старые `config.yaml` / `catalog.yaml` и JSON-реестры **больше не читаются и не мигрируют** (файлы остаются как есть); при обновлении до 1.0.0 конфигурацию нужно **настроить заново**. Подробности — в [docs/upgrades/1.0.0-sqlite-breaking.md](docs/upgrades/1.0.0-sqlite-breaking.md).
