# Глоссарий (Glossary)

Здесь только предметные термины, без деталей реализации.

## О промптах

- **Секция системного промпта (System Prompt Section, сокращённо «секция»)**: единица содержимого, которая вставляется в «системный промпт». Панель умеет показывать/блокировать её (а также уже существующие замена, добавление и сортировка). С 2.1.0 неважно, в каком слое зарегистрирована секция — global / preset / agent, — все они динамически перечисляются в панели редактирования пресета (ADR-0005).
- **Контекст времени выполнения (Runtime Context, contexts)**: дополнительное содержимое, которое хост передаёт при сборке. Та его часть, что **вливается в системный промпт**, считается «секцией системного промпта», и её можно показывать/блокировать; настоящие сообщения роли user, результаты инструментов и прочее, что **в системный промпт не вливается**, вне зоны ответственности этой системы.
- **Секция, регистрируемая при первом запуске (First-run Registered Section)**: секция системного промпта, которую плагин регистрирует только в момент первого монтирования/запуска, — включая сессионные секции, динамически зарегистрированные в `agent/created` через `agent.ctx.systemPrompt.section()`. Это именно «секция»: её нужно динамически перечислять и давать блокировать/показывать (ADR-0005).
- **Источник (Source)**: **слой регистрации**, в котором находится запись: global / preset (с id пресета) / agent (с id сессии) / executor / workspace; если хост может дать provider id, он тоже добавляется. Нужен, чтобы различать одинаковые имена из разных источников. У источника agent во время выполнения есть id сессии, но **в списке и предпросмотре он единообразно сводится к `{kind:'agent'}`** (без id), чтобы конфиг, сохранённый по пресету, срабатывал в любой сессии (2.1.0 / ADR-0005 D4).
- **Идентичность записи (Entry Identity)**: общий идентификатор для секций, инструментов и рантайм-контекста = **имя + источник**; одинаковые имена из разных источников — разные записи.
- **Идентичность секции (Section Identity)**: идентификатор секции = **имя + источник** (идентичность записи в применении к секциям).
- **Предпросмотр реальной сборки (Real Assembly Preview)**: содержимое предпросмотра = **системный промпт, который фактически уходит модели** после реальной сборки «этот пресет + активный агент того же пресета»; только секции системного промпта, без объявлений инструментов, schema и сигнатур. Если активной сессии нет (или у пресета нет активного агента), предпросмотр откатывается к варианту «прогнать реальную сборку этого пресета один раз». С 2.1.0 текст промпта, а с 2.1.2 и каталог инструментов в правой колонке — из того же источника, что read-only `/session` (источник данных об инструментах — `ctx.tools.schemas(agent)`, а не сборка пресета).

## Об инструментах

- **Секция промпта инструмента (Tool Prompt Section)**: `systemPrompt.section`, зарегистрированная как `tool:<name>` или `tool:<group>`; это первая часть инструмента. Одна секция может обслуживать несколько инструментов (например, jobs / pty / goal / schedule / subagent) и не зависит от description инструмента и JSON Schema.
- **Описание инструмента (Tool Description)**: `description` в объявлении инструмента, идёт через `GenerateOptions.tools`, **не является секцией системного промпта**; плагин не может скрыть или отредактировать его отдельно — только управлять инструментом целиком через «видимость инструментов» (ADR-0005 явно исключает это).
- **Сигнатура инструмента (Tool Schema / Signature)**: объявление инструмента (имя, `description`, JSON schema параметров, сигнатура функции). **Не редактируется**; доступность определяется только через «видимость инструментов».
- **Видимость инструментов (Tool Visibility)**: управляет тем, доступен ли инструмент модели (включён/выключен).
- **Пул скрытых (Masked Pool)**: строки **инструментов** в read-only пуле «Полный каталог / скрытые»: инструмент, ограниченный `restrict` другого плагина (`masked-plugin`), скрытый собственным MCP плагина (`masked-own`), перекрытый одноимённым инструментом плагина в скоупе agent (`masked-shadow`, 2.1.1), а также инструмент, который плагин в скоупе agent **добавляет с нуля** и у которого в унаследованных слоях нет одноимённого оригинала (`locked-agent`, с 2.1.2 честно показывается как «уровень сессии», не выдавая его за скрытый). Блокировка секций идёт через списки конфига `sections*` и в пул скрытых не попадает.
- **Список включённых (Enabled List)**: набор инструментов, которые модель сейчас видит / может использовать.
- **Идентичность инструмента (Tool Identity)**: идентификатор инструмента = **имя + источник** (одинаковые имена из разных источников — разные записи инструментов).
- **Реестр глобальных MCP (Global MCP Ledger)**: набор глобальных MCP Server, хранящийся в `$DSH_HOME/mcps/<serverName>/mcp.json` (стандартный формат `.mcp.json`, намерение «включён/выключен» — в соседнем `.dsh-prompt-customizer.json` в том же каталоге). Глобальные добавление / включение-выключение / удаление / редактирование из панели пишутся именно сюда, а после старта плагин возвращает их в память root Loader; в хостовый `cordis.yml` они не пишутся.

## Пресеты и уровни

- **Изоляция пресетов (Preset Isolation)**: секции и инструменты разных пресетов агента не смешиваются; список и предпросмотр отражают только реальную сборку «этот пресет + активный агент того же пресета» и никогда не подменяются сессионными секциями из сессии другого пресета (ADR-0005 D5).
- **Уровень пресета (Preset Level)**: единственная активная привязка кастомизации промптов/инструментов; сохранение и действие — по пресету агента. Уровень воркспейса для промптов/инструментов удалён (исходники заархивированы, данные в спящем режиме).
- **Три фазы (Three Phases)**: фаза ввода (`bootstrap`) / фаза управляемого сжатия (`compaction`) / постоянная фаза (`active`).
- **Синхронизация фаз (Three-phase Sync)**: когда включена, изменения секций, инструментов и рантайм-контекста применяются сразу во всех трёх фазах.
- **Архив уровня воркспейса (Workspace-level Archive)**: исходники промптов/инструментов уровня воркспейса остаются в исходных каталогах для справки, но не участвуют в точках входа, сборке, маршрутизации, бэкапах и отображении; поле данных `workspaceOverrides` в спящем режиме.
- **Обобщённая сессионная запись (Generic Session Item)**: сессионная запись, динамически зарегистрированная плагином в скоупе agent. С 2.1.0 в список / предпросмотр пресета попадают только такие записи **активного агента того же пресета**; при переключении на другой пресет они не примешиваются (ADR-0005 D5).
- **Замена с привязкой к фазе (Phase-scoped Replacement)**: текстовая замена, действующая только на уже существующие секции и отдельно по каждой фазе (always/bootstrap/active/compaction); новых секций не создаёт никогда.
- **Таблица описателей фаз (Phase Descriptor Table)**: единственная описательная таблица трёх фаз (key, поля секций, поля контекста, поля инструментов, состояние); все модули порождаются ею, три рукописные карты запрещены.
- **Расширенное сканирование скиллов (Skill Scan Upgrade)**: сканирование корней скиллов воркспейса, которое выполняет этот плагин; ядро `snapshot()` не покрывает skills/MCP воркспейса, поэтому сканирование выполняется всегда и его результаты сливаются с записями ядра.
